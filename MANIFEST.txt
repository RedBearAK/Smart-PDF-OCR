WHAT CHANGES

  Default outputs move into a per-run, per-document folder. A bare

      smart-pdf-ocr FILENAME.pdf

  now creates FILENAME_smartocr_files_<HHMMSS>/ BESIDE the input (time-only
  stamp: the scan names already carry the date) holding

      FILENAME_corrected.txt
      FILENAME_review.tsv
      FILENAME_smartocr.pdf

  replacing the old defaults (corrected text to stdout, no review file, no
  PDF) that pushed every path onto the command line and produced generic
  colliding names. Rules:

  - Explicit -o / --review-out / --pdf-out win per artifact, land exactly
    where stated, never relocated into the folder. All three explicit ->
    no folder at all.
  - --output-dir DIR redirects the folder (created if needed, reusable;
    the per-file --force overwrite guards still apply inside).
  - -o -  dumps corrected text to stdout (the old no-flag behavior).
  - The auto folder is refused if it already exists; a preflight failure
    removes the just-created empty folder again.
  - The searchable PDF defaults on only for a real PDF input with pikepdf
    present; otherwise "searchable PDF skipped: pikepdf not installed" and
    the run proceeds.
  - --learn-profile is untouched: a standing, accumulating file, not a
    per-run artifact. --cached runs default the text and review files
    (named after the cache) but never a PDF (nothing to sandwich).
  - Defaults resolve BEFORE the fail-early preflight, so defaulted paths
    inherit every existing guard (overwrite refusal, input-collision,
    duplicate-target) unchanged.

  The old GalaxSea runbook invocation keeps working verbatim; it can now
  shrink to:

      smart-pdf-ocr --report \
        --known-patterns known_patterns.txt \
        --error-patterns error_patterns.txt \
        --learn-profile galaxsea.json \
        FILENAME.pdf

  and gxy-charges-sheet pointed at the folder's corrected file drops its
  timestamped workbook alongside, named from the source line.

TESTS
