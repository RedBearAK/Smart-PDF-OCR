WHAT CHANGES

  The input-side mirror of ocr_outdirs: the standing files leave the
  invocation. When --known-patterns / --error-patterns / --profile /
  --learn-profile are omitted, a _smartocr_support folder BESIDE the input
  (leading underscore, sorts above the documents; --support-dir overrides)
  supplies:

      known_patterns.txt
      error_patterns.txt
      <anything>.json         the vendor profile

  Rules:

  - Announced, never silent:
      support: .../_smartocr_support (known_patterns.txt, error_patterns.txt,
               profile galaxsea.json (load+update))
  - An explicit flag wins for that file, exactly as on the output side.
  - A lone .json becomes BOTH ends of the profile round-trip: loaded
    before the run and updated by learning after it, so canonicals
    compound across runs (the old runbook wrote galaxsea.json every run
    but never loaded it back). Two or more .json files are refused BY
    NAME with the flag to pass -- no guessing.
  - A missing auto folder is an unconfigured folder, not an error; a
    missing --support-dir is an error.
  - Round-trip exemption in the overwrite guard: --learn-profile pointing
    at the same file as --profile no longer demands --force -- updating a
    file you are also loading is declared intent, like --review-in with
    --review-out. (Standing friction fixed: repeat --learn-profile runs
    previously exited 2 without --force.)

  The GalaxSea workflow becomes: put known_patterns.txt,
  error_patterns.txt and galaxsea.json in _smartocr_support once; the
  user drops PDFs in the folder and runs

      smart-pdf-ocr FILENAME.pdf

  (--report to taste). The working folder holds nothing but documents,
  their run folders, and the support folder.
